# 02 · 数据获取与合规（已验证版）

> 本文回答：数据从哪来、怎么拿、拿到什么形状、拿不到怎么办、哪些事不能做。
> **所有接口均在 2026-11-08 用真实账号验证通过**，代码如下：
> `apps/server/src/import/nju.ts`、`apps/server/src/adapters/ehall/`、`apps/server/scripts/`。

---

## 1. 结论先行

| 问题 | 答案 |
| --- | --- |
| 前端能不能直接抓 ehall？ | 不能。CORS + HttpOnly Cookie + 统一认证三重墙 |
| 能不能用账号密码自动登录？ | **现在不能**。统一认证已启用滑块验证（`toSliderCaptcha`），本项目不做验证码绕过 |
| 实际采用的主路径 | 浏览器登录一次 → 导入会话 Cookie（应用内粘贴，或本地脚本从受控浏览器导出）→ 服务端只读抓取 |
| 已验证可用的应用 | `wdkb` 我的课表、`kcbcx` 本-课表查询（开课/教学班）、`cjcx` 成绩、`qxfacx` 培养方案、`xyyj` 学业预警 |
| 抓一次要多久 | 约 30–40 秒（3216 个教学班分 4 页） |
| 数据存哪 | `apps/server/data/`（已 gitignore），JSON；Cookie 单独存放，同样不入库 |

## 2. 认证链路（实测）

### 2.1 三个域名

| 域名 | 作用 |
| --- | --- |
| `authserver.nju.edu.cn` | 统一身份认证（金智 CAS） |
| `ehall.nju.edu.cn` | 网上办事服务大厅（门户、应用列表） |
| `ehallapp.nju.edu.cn` | 业务应用（jwapp），数据接口所在 |

### 2.2 登录流程

```
访问 https://ehallapp.nju.edu.cn/jwapp/sys/<app>/*default/index.do
  → 302 https://authserver.nju.edu.cn/authserver/login?service=<app 页面>
  → 登录页（execution、pwdEncryptSalt、滑块验证）
  → 用户完成账号密码 + 滑块
  → 302 回 ehallapp?ticket=ST-xxx
  → ehallapp 建立会话 Cookie
```

实测要点：

1. `https://ehall.nju.edu.cn/` 本身是公开门户，**不会**跳登录；必须从 biz app 页面进入才会触发 CAS。
2. 登录页确实包含 `execution` 与 `pwdEncryptSalt`（例如 `e1s1` / 16 位随机串）。
3. 登录页加载 `toSliderCaptcha` / `openSliderCaptcha` / `verifySliderCaptcha`，**滑块验证是登录流程的一部分**。
4. 密码加密（页面 `encrypt.js` 的 `encryptPassword`）：
   ```
   plaintext = randomString(64) + password
   key       = pwdEncryptSalt
   iv        = 随机 16 字符（JavaScript 侧；服务端按固定 IV 处理）
   cipher    = AES-128-CBC + PKCS7 → Base64
   ```
   参考实现（PyPI `nju-login-simple`）使用固定 IV `"a"*16` 并提交 `username/password(_eventId 等隐藏字段)`。
   **该路径因滑块验证暂不可用**，代码保留为实验性分支（`adapters/ehall/cas.ts`），失败时明确返回 `CAPTCHA_REQUIRED`。

### 2.3 为什么不绕过验证码

- 项目边界（选题说明）明确「不依赖非公开接口、不保存凭证」；
- 滑块验证属于访问控制，绕过它既不稳定也不合规；
- 浏览器登录 + 导入 Cookie 的体验成本只有一次点击，换来的是长期稳定。

## 3. 已验证的接口

所有请求均为 `POST`，`Content-Type: application/x-www-form-urlencoded`，
携带 `Cookie`；响应 `{ code:"0", datas:{ <name>:{ rows:[...] } } }`。

| 用途 | 路径 | 关键参数 | 返回 |
| --- | --- | --- | --- |
| 学生信息 | `/jwapp/sys/xyyj/modules/xsxyyjjg/cxxsjbxx.do` | 无（默认本人） | 学号、姓名、院系、专业、班级、年级 |
| 学业预警批次 | `/jwapp/sys/xyyj/modules/xsxyyjjg/cxxsyjpcjg.do` | 无 | 批次名、级别、是否预警 |
| 预警课程明细 | `/jwapp/sys/xyyj/modules/xsxyyjjg/cxlbxssj.do` | `*order=+XNXQDM,+KCH&pageSize=100&pageNumber=1` | 每门课的通过情况；**含 PYFADM** |
| 当前学期 | `/jwapp/sys/kcbcx/modules/bjkcb/dqxnxq.do` | 无 | `DM=2026-2027-1` |
| 培养方案（按 ID） | `/jwapp/sys/qxfacx/modules/pyfacxepg/qxpyfacxzl.do` | `querySetting=[{"name":"PYFADM","value":"...","builder":"equal"}]` | 方案名、总学分、修读要求文本（XDYQ）、年级、专业 |
| 成绩 | `/jwapp/sys/cjcx/modules/cjcx/cxxscjd.do` | `pageSize=300&pageNumber=1` | 课程号/名、学分、成绩、学期、课程性质 |
| 我的课表 | `/jwapp/sys/wdkb/modules/xskcb/cxxskclb.do` | `XNXQDM=2026-2027-1&pageSize=100&pageNumber=1` | 本学期已选课程（含时间地点字符串） |
| 开课与教学班 | `/jwapp/sys/kcbcx/modules/qxkcb/qxfbkccx.do` | `*json=1&querySetting=[XNXQDM]&pageSize=999&pageNumber=N` | 全校教学班：课程、教师、时间、教室、容量、校区 |

> ⚠️ `qxkcb.do`（模块级路径）只返回**页面配置**（models/routes），不是数据。
> 数据在子路径 `qxkcb/qxfbkccx.do`。这是抓包里最容易踩的坑。

### 3.1 关键字段

| 语义 | 字段 | 示例 |
| --- | --- | --- |
| 课程号 | `KCH` | `25000310` |
| 课程名 | `KCM` | `软件工程与计算 I` |
| 学分 | `XF` | `4`（成绩单里可能是字符串） |
| 教学班 | `JXBMC` / `KXH` | `软件工程与计算 I01班` / `01` |
| 教师 | `SKJS` | `张三,李四` |
| 时间（结构化） | `SKXQ` / `SKJC` / `SKZC` | `周五,周六` / `第5节-第7节,...` / `1-18周,1-18周` |
| 时间（可直接展示） | `YPSJDD` | `周五 5-7节 1-18周 苏教B206, 周六 2-4节 1-18周 苏教B206` |
| 教室 | `SKJAS` | `苏教B206, 苏教B206` |
| 校区 | `XXXQDM_DISPLAY` | `仙林校区` |
| 通修类别 | `TXKCLB_DISPLAY` | `思政课 / 数学课 / 英语课 / 计算机 / 体育课` |
| 课程性质（成绩单） | `KCXZDM_DISPLAY` | `通修 / 通识 / 平台 / 核心 / 选修` |
| 已选人数/容量 | `XKZRS` / `KRL` | `39` / `50` |

### 3.2 学期与"未发布"状态

- 学期列表来自 `code` 接口（`/jwapp/code/<uuid>.do`），也可从成绩/课表行的 `XNXQDM` 推导；
- **2026-11-08 实测：2026-2027-2 的课表尚未发布**，`qxfbkccx.do` 返回
  `{"extParams":{"msg":"2026-2027学年 第2学期的课表未发布"},"rows":[]}`；
- 因此同步逻辑会尝试下一个学期，若未发布则回落到当前学期，并在来源卡片里标注
  「（当前学期）」，方案备注写「下学期开课数据尚未发布，暂以本学期课表为参考」。

## 4. 采集策略（最终版）

| 策略 | 体验 | 稳定性 | 合规 | 采用 |
| --- | --- | --- | --- | --- |
| 浏览器登录 + Cookie 导入 | 一次点击（粘贴）或脚本自动导出 | 高 | 只读、本人 | ✅ **主路径** |
| 服务端 CAS 登录 | 无需浏览器 | 低（滑块验证） | 不绕过验证码 | ⚠️ 实验性，遇到验证码即停 |
| 浏览器扩展同源抓取 | 最顺滑 | 高 | 需用户授权扩展 | ⛔ 后续可选 |
| 手动导入 CSV/JSON | 最麻烦 | 最高 | 无 | ⛔ 兜底未实现 |

三种导入方式（应用内）：

1. **粘贴 Cookie**：开发者工具 → Network → 任意请求 → 复制 Cookie 头 → 登录页「粘贴 Cookie」。
2. **脚本导出**（推荐给开发/答辩）：
   ```bash
   node apps/server/scripts/edge-cookies.mjs --domain nju.edu.cn --out apps/server/data/cookies.json
   ```
   从受控 Edge（CDP :9333）读取当前会话 Cookie，不经过剪贴板。
3. **命令行同步**：
   ```bash
   pnpm --filter @planner/server sync:real
   ```
   抓取 → 映射 → 覆盖 `data/db.json`（首次会备份为 `db.demo.json`）。

## 5. 字段映射与归类规则

`src/import/nju.ts` 的 `mapBundleToDb()` 负责把五类原始数据变成领域模型。

### 5.1 培养方案

教务返回的 `XDYQ` 文本：

> 本专业学制四年，专业应修总学分150学分，其中通识通修课程（必修）61学分，学科专业课程（必修）49学分，
> 多元发展课程（选修）34学分，毕业论文/设计（必修）6学分。

据此生成 4 个模块（`RequirementNode`），并要求：

| 模块 | 要求 | 匹配规则 |
| --- | --- | --- |
| 通识通修课程 | 61 | 标签含 `通修` 或 `通识` |
| 学科专业课程 | 49 | 标签含 `学科专业` |
| 多元发展课程 | 34 | 标签含 `多元发展` |
| 毕业论文/设计 | 6 | 标签含 `毕业论文` |

> 这是**模块级**要求，不是教务内部的"课组级"要求（如"思政 16 学分""外语 8 学分"）。
> 课组明细接口尚未找到（页面详情是前端渲染，无独立请求），因此 v1 采用模块级核算，
> 并在界面上写明口径，不假装更精确。

### 5.2 课程 → 模块

优先用成绩单里的 `KCXZDM_DISPLAY`；课程库没有该字段，用**课程号前缀**推断：

| 前缀 | 标签 | 依据 |
| --- | --- | --- |
| `000` | 通修 | 55 门已修课程中 25 门全部命中 |
| `002` `003` `004` `006` | 通识 | 13 门全部命中 |
| `2500` | 学科专业 | 平台 + 核心共 12 门全部命中 |
| `2501` | 多元发展 | 选修 5 门全部命中 |

实测 **55/55 与教务口径一致，0 冲突**。但它仍是推断：换专业/换年级可能失效，
所以界面上标注「课程库按课程号前缀推断」。

### 5.3 时间解析

`YPSJDD` 一行可能包含多段：

```
周五 5-7节 1-18周 苏教B206, 周六 2-4节 1-18周 苏教B206
```

按 `, ` 切分后逐段解析：星期、节次、周次（复用 `parseWeeksText`，支持 `1-7周(单)`、`3-4周,8-9周`）、地点。
`自由时间 2-18周 自由地点` 解析为空排课 → 界面显示「无固定上课时间」。

### 5.4 在修课程

成绩单只到 2025-2026-2；本学期课程来自 `wdkb` 课表：
- 写入 `Section.inCurrentTimetable = true`；
- 同时写一条 `status: "in-progress"` 的成绩记录（不计已获学分，但参与"计划覆盖"）；
- `collectPlannedCourses` 会对「在修 + 方案里同一门课」去重，避免计划学分翻倍。

## 6. 同步链路（运行时）

```
POST /api/sync
  → requireSession（必须是 cas/cookie 会话）
  → CookieJar.header(ehallapp) 生成 Cookie 头
  → fetchNjuBundle()：8 个请求，分页抓 3216 个教学班
  → mapBundleToDb()：重建课程/教学班/成绩/方案/来源
  → 保留用户自建方案（过滤掉已不存在的教学班）
  → Store.replace() 原子写盘
  → 返回 summary（成绩条数、教学班数、在修门数、学期）
```

耗时约 30–40 秒，期间前端按钮显示「同步中…」，不做假进度。

## 7. 合规清单

| 要求 | 落地 |
| --- | --- |
| 最小必要 | 只请求五类数据 |
| 目的限制 | 仅本人课程规划，界面与 README 明示 |
| 不存密码 | 密码只在 `casLogin()` 栈内存活；Cookie 导入不含密码 |
| 加密存储 | 服务端会话中的 Cookie 罐 AES-256-GCM；`cookies.json` 只落在本地 data 目录 |
| 可删除 | 删除 `apps/server/data/` 即清除全部个人数据 |
| 不越权 | 只使用当前会话；无他人查询接口 |
| 不绕过验证 | 遇滑块返回 `CAPTCHA_REQUIRED`，引导 Cookie 导入 |
| 只读 | 无任何写接口调用；正式选课仍由学校系统完成 |
| 域名白名单 | `requestWithJar` 只允许三个南大域名（防 SSRF） |
| 演示数据分离 | 开发用 `db.demo.json`；文档截图使用演示数据，不含真实姓名学号 |

## 8. 风险与降级

| 风险 | 已发生？ | 应对 |
| --- | --- | --- |
| 滑块验证阻断密码登录 | ✅ | Cookie 导入（已实现） |
| 模块级 `qxkcb.do` 返回的不是数据 | ✅ | 改用 `qxkcb/qxfbkccx.do` |
| 下学期数据未发布 | ✅ | 回落到当前学期并标注 |
| 教务改版字段变化 | 未 | `remap` 只改映射、不重新抓取；`real-bundle.json` 可重放 |
| Cookie 过期 | 未 | 同步时检测空数据 → 401 + 提示重新登录 |
| 课组级要求缺失 | ✅ | 只做模块级核算，界面写明口径 |
