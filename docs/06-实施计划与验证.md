### 5.2 适配层测试（M2 必做）

```
fixtures/
├─ kcbcx-2026-2027-2.json      # 真实响应脱敏后的快照
├─ qxfacx-pyfa.json
├─ cjcx-transcript.json
└─ xyyj-warnings.json
```

断言：
1. 每份快照都能解析出 ≥ N 条记录；
2. 周次文本解析结果与人工核对一致（覆盖 `1-16周(单)`、`3-11周(单),13-16周`）；
3. 缺失字段（如无周次）不会导致整行丢弃，而是 `meeting = null` + `ambiguous` 标记。

## 6. 用户研究方案

### 6.1 访谈（5–8 人，30 分钟）

**筛选**：近两个学期内有过选课经历，且至少有一次「在几门课之间犹豫」的经历。

**提纲**：
1. 上一次选课前一晚，你在哪些页面之间来回？能复述顺序吗？（观察信息路径）
2. 你怎么知道「还差多少学分」？有没有算错过？
3. 有没有遇到过单双周判断失误？后来怎么发现的？
4. 你有几套方案？存在哪？（Excel/备忘录/截图）
5. 最后怎么定下来的？哪一刻觉得「可以了」？
6. 如果有一个工具能替你做一件事，你最想让它做哪件？

**产出**：信息路径图、错误案例清单、功能优先级排序。

### 6.2 任务观察（同一批人，20 分钟）

**任务**：
> 「下学期你要修完专业核心必修，社会科学类还差 4 学分，周三全天不在校。请用这个工具制定一套无冲突方案，并导出清单。」

**角色**：主持人（读题、不提示）、记录员（计时、数页面切换、记错误）。

**度量**：

| 指标 | 采集方式 |
| --- | --- |
| 完成时间 | 计时器 |
| 视图切换次数 | 录屏编码（每次路由切换/抽屉开关计 1） |
| 错误操作 | 「加入后又撤销」「选错教学班」等 |
| 求助次数 | 口头求助计 1 |
| 主观难度 | 1–7 量表 |
| SUS | 10 题标准问卷 |

**对照**：同一任务在现有网站（或脚本中的手工流程）上做一次，比较时间与切换次数。
样本小（n=5–8），只用于发现问题，不做统计推断——这一点要写进报告，避免过度声称。

### 6.3 迭代闭环

每个问题记录：现象 → 影响（卡在哪一步）→ 假设 → 修改 → 复测。
优先级：**阻塞任务 > 高频摩擦 > 视觉细节**。

## 7. 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| ehall 接口无法确认 | 中 | M2 延期 | 降级为「粘贴 Cookie + 手动快照导入」；演示模式不受影响 |
| CAS 加密方式不匹配 | 中 | 无法真实登录 | 用 Cookie 导入先跑通业务流程；加密问题单独排查 |
| 培养方案规则与学校口径不一致 | 高 | 数字可信度受质疑 | 界面明示口径；允许用户手动调整模块要求（M3） |
| 测试样本偏差（都是本专业） | 高 | 结论外推受限 | 报告中明确样本局限；补充 1–2 个跨专业访谈 |
| 时间不足 | 中 | 功能砍掉 | 已按 MoSCoW 排序；M3/M4 可裁剪 |
| 数据隐私争议 | 低 | 项目受阻 | 本地部署、只读、可删除、演示数据脱敏 |

## 9. 答辩时可以讲的三个「设计决策」

如果只有三分钟，讲这三件事，它们最能体现 HCI 的设计含量：

1. **为什么必须做后端**：CORS + CAS Cookie + 验证码三重墙，推理链完整（不是「因为需要数据库」）。
2. **为什么冲突要精确到格子**：演示同一门课周一冲突、周三不冲突的场景，说明「整门标红」会造成误判。
3. **为什么默认 5 天**：7 列时课程名会被拆成竖排（可展示截图对比），这是从可读性反推的布局决策。
