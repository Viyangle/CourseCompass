# 04 · 系统架构与接口

> 本文回答：代码怎么分层、请求怎么走、接口长什么样、以后怎么扩展。
> 代码：`apps/web`、`apps/server`、`packages/shared`。

---

## 1. 运行拓扑

### 1.1 开发态

```
┌────────────────────────────┐        ┌─────────────────────────────┐
│ Vite dev server :5173      │        │ Fastify :8787               │
│  · Vue SFC HMR             │  /api  │  · /api/*                   │
│  · 静态资源                │ ─────▶ │  · 会话 Cookie              │
└────────────────────────────┘ proxy  └───────────┬─────────────────┘
                                                  │ 仅本人会话
                                                  ▼
                                   authserver.nju.edu.cn / ehallapp.*
```

同源代理的意义：Cookie 是 `SameSite=Lax`，跨端口开发也不产生跨站问题；生产环境完全同源。

### 1.2 生产态（单进程）

```
Fastify :8787
├─ /api/*        → 路由
├─ /assets/*     → apps/web/dist（@fastify/static）
└─ 其余           → index.html（SPA fallback）
```

```bash
pnpm build && pnpm start
```

这是刻意的「单进程」选择：课程项目需要在同学的笔记本上 `pnpm dev` 就能跑，多一个 Nginx 只会增加失败点。

## 2. 分层

```
apps/server/src
├─ routes/           HTTP 边界：解析、校验、组装响应（不写业务）
│  ├─ auth.ts        登录/登出/会话
│  ├─ data.ts        bootstrap、catalog、program、courses、sources、sync、analysis
│  ├─ plans.ts       方案 CRUD、items 全量替换、compare、export
│  └─ dev.ts         探针与快照（DEV_TOOLS=1）
├─ services/         应用服务：编排领域能力
│  ├─ analysis.ts    冲突 + 指标 + 覆盖率（调用 shared）
│  ├─ catalog.ts     课程检索（缺口、冲突、状态）
│  ├─ export.ts      Markdown / CSV / ICS
│  └─ session.ts     内存会话 + 演示会话持久化
├─ adapters/ehall/   外部系统适配：CAS、Cookie、jwapp、字段映射
├─ store/            JSON 持久化 + 种子数据
└─ lib/              错误信封、加密、脱敏
```

规则：**routes 不写业务，services 不碰 HTTP，shared 不依赖 Node**。
`packages/shared` 必须保持纯函数，才能被浏览器直接引用。

## 3. 关键数据流

### 3.1 首次加载

```
GET /api/session            → 未登录 → 前端跳 /login
POST /api/auth/login demo   → Set-Cookie: planner_session
GET /api/bootstrap          → 画像、学期、方案、成绩、来源
GET /api/catalog            → 课程 + 教学班（一次性）
GET /api/plans              → 每个方案附带服务端分析
```

前端只发 4 个请求就能渲染全部页面。**没有 N+1，没有按需分页**——数据量决定了这样更简单也更快。

### 3.2 拖入一门课（核心交互）

```
用户拖拽 → planner.addSection(sectionId)
        → 本地立即重算（分析是 getter，数据变更即失效）
        → 界面在下一帧更新：课表、学分、冲突、缺口
        → 420ms 防抖后 PUT /api/plans/:id/items
        → 服务端校验 + 重新分析 + 返回权威结果
        → 前端用返回值覆盖本地 plan（仅在成功时）
```

失败处理：`saveState = 'error'`，顶栏显示「保存失败」，但**本地状态不回滚**——用户的操作不应该被网络问题吞掉。
下一次成功保存会自动同步全部 items（全量替换的收益）。

### 3.3 全量替换而不是增量

`PUT /api/plans/:id/items` 接收完整列表：

- 前端撤销栈只需保存 `items` 快照；
- 拖拽中的多次变更合并为一次请求；
- 不会出现「服务端多了一条、前端不知道」的中间态；
- 代价是请求体稍大（≤ 30 项），可忽略。

### 3.4 方案对比

```
GET /api/compare?ids=plan-a,plan-b
→ 逐个方案 analyzePlan
→ 取课程并集，构造 presence / conflictCount 矩阵
→ 前端直接渲染成三块表
```

## 4. REST 接口

统一响应信封：

```json
{ "ok": true, "data": { ... } }
{ "ok": false, "error": { "code": "UNAUTHORIZED", "message": "会话已过期，请重新登录", "details": {} } }
```

### 4.1 认证

| 方法 | 路径 | 入参 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/session` | — | 当前会话（未登录也返回 200，`authenticated:false`） |
| `POST` | `/api/auth/login` | `{method:'demo'}` / `{method:'cas',username,password}` / `{method:'cookie',cookie}` | 三种方式，返回 `SessionInfo` |
| `POST` | `/api/auth/logout` | — | 销毁会话 |

`SessionInfo`：`{ authenticated, method, profile, expiresIn, offline }`。
`offline` 为 true 表示当前使用演示数据（界面显示「演示数据」角标）。

### 4.2 数据

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/bootstrap` | 一次拿齐：学期、画像、培养方案、成绩、预警、方案、来源 |
| `GET` | `/api/catalog?termId=` | 课程库 + 教学班 + 本学期课表（前端本地筛选） |
| `GET` | `/api/program?planId=` | 培养方案 + 进度（含指定方案的计划部分） |
| `GET` | `/api/transcript` | 成绩记录 + 学业预警 |
| `GET` | `/api/courses?...` | 服务端筛选（保留给未来的大课程库；当前界面用 `/catalog`） |
| `GET` | `/api/courses/:code` | 课程详情 + 教学班 + 修读记录 |
| `GET` | `/api/sources` | 数据来源 + 最近快照 |
| `POST` | `/api/sync` | `{sources?: string[]}`；演示模式只刷新时间戳，真实模式在接口未确认时返回 409 + 指引 |
| `GET` | `/api/analysis/:planId` | 单个方案的完整分析 |

### 4.3 方案

| 方法 | 路径 | 入参 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/plans` | — | 方案列表 + 每个方案的分析摘要 |
| `POST` | `/api/plans` | `{name, termId?, copyFrom?}` | 新建（可复制现有方案） |
| `PATCH` | `/api/plans/:id` | `{name?, note?, color?}` | 重命名/备注/颜色 |
| `DELETE` | `/api/plans/:id` | — | 删除；最后一个方案不可删（`LAST_PLAN`） |
| `POST` | `/api/plans/:id/duplicate` | — | 复制 |
| `PUT` | `/api/plans/:id/items` | `{items:[{sectionId,status,note?}]}` | 全量替换，返回最新 plan + analysis |
| `GET` | `/api/plans/:id/analysis` | — | 冲突 + 指标 + 覆盖度 |
| `GET` | `/api/compare?ids=a,b,c` | 1–4 个 id | 对比矩阵 |

### 4.4 导出

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/export/:planId?format=md\|csv\|ics` | 附件下载；文件名 URL 编码 |

- `md`：人读清单（含课程号、教学班、教师、时间、地点、考核）
- `csv`：带 BOM，Excel 直接打开
- `ics`：每段排课一个 `VEVENT`，`RRULE` 处理单双周（`INTERVAL=2`），`TZID=Asia/Shanghai`

### 4.5 开发工具（`DEV_TOOLS=1`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/dev/probe` | `{appId,module,method,form?}` 用当前会话试接口，返回行数/字段名，成功则存快照 |
| `POST` | `/api/dev/capture` | `{url,method,headers?,body?}` 重放浏览器复制的请求 |
| `GET` | `/api/dev/snapshots` | 快照索引 |

### 4.6 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | 未登录/会话过期 |
| `BAD_REQUEST` | 400 | 参数不合法（zod） |
| `NOT_FOUND` | 404 | 方案/课程不存在 |
| `SECTION_NOT_IN_TERM` | 400 | 教学班不属于方案学期 |
| `LAST_PLAN` | 409 | 不允许删除最后一个方案 |
| `CAPTCHA_REQUIRED` | 401 | 统一认证要求验证码 |
| `CAS_LOGIN_REJECTED` | 401 | 用户名/密码错误或加密方式变化 |
| `CAS_FORM_CHANGED` | 401 | 登录页字段解析失败 |
| `NETWORK_ERROR` | 401 | 无法访问认证服务 |
| `ENDPOINTS_UNVERIFIED` | 409 | 已登录但业务接口未确认 |
| `NO_EHALL_SESSION` | 409 | 探针会话中没有 ehall Cookie |
| `HOST_NOT_ALLOWED` | 500 | 请求了白名单外的域名（经日志暴露，前端只看到 `INTERNAL_ERROR`） |
| `INTERNAL_ERROR` | 500 | 未捕获异常（不返回堆栈） |

## 5. 前端架构

### 5.1 状态划分

| Store | 职责 | 关键点 |
| --- | --- | --- |
| `session` | 登录状态、错误与提示 | 登录失败保留 `errorHint`（如「先连 VPN」） |
| `data` | 只读数据：学期、培养方案、成绩、课程库、方案列表 | `load()` 幂等；`catalog` 与 `bootstrap` 分开 |
| `planner` | 可写状态：当前方案、周次、撤销栈、保存状态 | **分析是 getter**，数据一变自动重算 |

### 5.2 为什么分析放 getter

```ts
analysis(): PlanAnalysis | null {
  const data = useDataStore();
  return analyzePlanLocal(this.activePlan, { ...deps });
}
```

好处：任何影响结果的输入（方案项、成绩、课程库）变化，依赖追踪自动触发重算，不需要手动 `watch`。
代价：每次读取都重算，但数据规模小（见 03 §6），可以接受。

### 5.3 撤销/重做

```
mutate 前：snapshot(label) → history.push({ planId, items: [...items] })
undo：history.pop() → future.push(当前) → plan.items = snapshot.items → persist(immediate)
```

- 上限 40 步，超出丢弃最早的；
- 只记录 `items`，不记录名称等元数据；
- 快捷键 `Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做；输入框内不拦截。

### 5.4 渲染策略

- 课表用「绝对定位块 + 相对定位列」而不是 `<table>`：块可以跨行、可以重叠（冲突时视觉叠压）、拖拽落点简单；
- 5 天/7 天可切换：默认 5 天，避免 7 列在窄容器里把课程名拆成竖排；
- 全部周/指定周：位掩码过滤，切换不重新请求。

## 6. 服务端细节

### 6.1 请求生命周期

```
Fastify
├─ @fastify/cookie        解析 planner_session
├─ 路由 handler
│  ├─ zod 校验入参
│  ├─ requireSession()    取会话，失败抛 AppError(401)
│  ├─ 调用 service
│  └─ ok(data)            统一信封
└─ setErrorHandler        记录日志（redact），返回 500 信封
```

### 6.2 持久化

`Store`：单文件 JSON + 300ms 防抖 + 原子替换（`write tmp → rename`）。
读时若 `version` 不匹配，用种子数据补齐缺失字段。写失败不回滚内存状态，下次写重试。

> 迁移到 SQLite 时只需要替换 `Store` 的实现：接口是 `data`（读取）、`touch()`（标记变更）、
> `flush()`（落盘）、`saveRaw()`（快照）。业务代码不感知存储形态。

### 6.3 安全

| 面 | 措施 |
| --- | --- |
| 会话固定 | 登录成功生成新 id；旧会话不重用 |
| XSS | 不用 `v-html`；会话 Cookie HttpOnly |
| CSRF | `SameSite=Lax` + 只接受 JSON 请求（跨站表单无法构造 `application/json`） |
| SSRF | `allowedHosts` 白名单，只允许三个南大域名 |
| 日志泄露 | `redact: ['req.headers.cookie','req.headers.authorization','req.body.password']` |
| 错误泄露 | 500 只返回通用文案，不返回堆栈 |
| 本地数据 | `apps/server/data/` 已 gitignore；可整体删除 |

## 8. 如何扩展

### 加一个数据来源（例如「我的考试安排」）

1. `apps/server/src/adapters/ehall/apps.ts` 增加一条 `EhallAppDef`；
2. 用探针确认 module/method，把 `verified` 改为 true；
3. `normalize.ts` 增加行映射；
4. `store/types.ts` 的 `Db` 增加集合，`seed.ts` 补演示数据；
5. `SourceKind` 增加枚举值，设置页自动出现（`sources` 由数据驱动）。

### 加一个页面

1. `views/XxxView.vue`；
2. `router.ts` 增加路由与 `meta.title`（顶栏自动显示）；
3. `AppShell.vue` 的 `nav` 增加一项；
4. 需要新数据时，优先复用 `/api/catalog` 与现有 store；只有跨页面共享的状态才新建 store。

### 换存储

实现 `Store` 的四个方法即可；`services/*` 只依赖 `Db` 类型，不依赖文件系统。
